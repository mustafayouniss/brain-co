## 13:18 — Next.js Runtime Security Upgrade to 16.4.6 (Runtime Remediation)

### Context & Root Cause
An audit revealed that although `frontend/package.json` specified `16.4.6`, `node_modules/` on both host and inside the Docker container executed `16.4.0`.
Root causes:
1. `npm install --package-lock-only` had previously updated lockfile metadata without extracting tarballs to host `node_modules`.
2. `frontend/.dockerignore` lacked `node_modules` and `.next`, causing un-upgraded host artifacts to be sent in the build context.
3. `frontend/Dockerfile` checked `if [ ! -d "node_modules" ]`, skipping `npm ci` when host `node_modules` was present in the build context.

### Remediation Applied
1. Executed `npm install` inside `frontend/` on host, unpacking `next@16.4.6`, `eslint-config-next@16.4.6`, and verifying React 19.3.0 alignment.
2. Updated `frontend/.dockerignore` to explicitly ignore `node_modules` and `.next`.
3. Updated `frontend/Dockerfile` to copy `package.json` and `package-lock.json`, run `npm ci --include=dev`, copy remaining sources, and run `npm run build`.
4. Rebuilt frontend image with `docker compose build frontend --no-cache` and recreated container via `docker compose up -d --no-deps frontend`.

## 13:37 — React Error #300 Root Cause Fix & Verification

### Root Cause
`frontend/src/components/floating-chat-widget.tsx` contained an early return statement (`if (isLoginPage) return null;`) on line 79 before two `React.useEffect` hook declarations (lines 87 and 96).
Because `FloatingChatWidget` is mounted globally in `RootLayout`, navigating between `/` (where 15 hooks were executed) and `/login` (where only 13 hooks were executed) caused React 19 to detect that fewer hooks were rendered than during the previous render, throwing `Uncaught Error: Minified React error #300`. Conversely, navigating from `/login` to `/` threw React error #310 ("Rendered more hooks than expected").

### Fix Applied
Relocated the conditional return `if (isLoginPage) return null;` below all 15 hook declarations in `frontend/src/components/floating-chat-widget.tsx`. All hooks now execute unconditionally in the exact same sequence on every render.
