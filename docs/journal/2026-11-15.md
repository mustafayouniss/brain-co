## SEC-02-F01: Fail-Closed Case Validation Remediation

### Context & Problem Statement
During an independent security audit of the Ring 1 General Brain module, `SEC-02-F01` was identified as a High severity vulnerability:
- `ContextEngine` failed open on client-supplied case boundaries when `self._case_validator is None` (the default unconfigured state), stamping untrusted client case IDs with `ResolutionStatus.EXPLICIT`.
- LLM inference fallback in `_try_llm_resolution` accepted inferred `case_id` directly without validation when `self._case_validator is None`.
- `self._case_validator` unhandled exceptions could crash execution or leak database internals to callers.
- Empty or whitespace-only scope strings were not strictly rejected.

### Actions Taken
1. **Engine Logic (`brain/src/brain/general/engines/context.py`)**:
   - Implemented private helper `_validate_case(self, org_id: str, case_id: str, user_id: Optional[str] = None) -> tuple[bool, str]`:
     - Rejects empty or whitespace-only strings.
     - Fails closed with `(False, "Access denied to case ...: no case validator configured to verify case scope.")` when `_case_validator is None`.
     - Fails closed when `_case_validator(...)` returns `False` or falsy.
     - Catches all exceptions, logs internal traceback via `logging.getLogger(__name__)`, and returns a safe generic authorization error (`"Access denied to case ...: authorization check failed."`) without leaking database internals.
   - Refactored `resolve_context()`:
     - Normalizes inputs and rejects empty/whitespace `case_id` or `scope_id` with `INVALID_SCOPE`.
     - Validates candidate client case IDs through `_validate_case()`, failing closed with `AUTHORIZATION_DENIED` when unverified.
     - Preserves server-side authoritative context while preventing client overrides (`FORBIDDEN_CASE_OVERRIDE`).
   - Refactored `handle_resolve()`:
     - Normalizes `hint_case` and rejects empty/whitespace values with `INVALID_PAYLOAD`.
     - Distinguishes trusted internal server provenance: only internal mesh engine delegations (`sender_engine != "client"`) carrying server cases bypass the validator when unconfigured. External client requests (`sender_engine == "client"`) are strictly validated and fail closed without a validator.
     - Rejects client case overrides matching server context with `AUTHORIZATION_DENIED`.
   - Hardened LLM Inference Fallback:
     - Downstream audit: If an LLM-inferred `case_id` cannot be verified by `_validate_case()` (including when `_case_validator is None` or raises an exception), `case_id` and `scope_id` are stripped to `None`, `resolution_status` is downgraded to `AMBIGUOUS`, and `scope_constraints` is sanitized to `["organization_id={server_org}"]` (eliminating `case_id` constraint).
     - Returns `status=ResultStatus.NEEDS_CLARIFICATION`, preventing unverified inferences from influencing downstream retrieval or mesh operations.
     - Sanitizes LLM string outputs in `_try_llm_resolution`.

2. **Test Suite Updates**:
   - Expanded `backend/tests/ring1/test_context_security_adversarial.py` to 21 comprehensive adversarial tests (from 8):
     - `test_context_explicit_hint_resolution_no_validator_fails_closed`
     - `test_context_explicit_hint_resolution_with_valid_validator`
