## Table: `users`

The first application table. Stores system operators (admins and employees). No multi-tenant fields; one organization per deployment (D-004).

### Schema (`\d users`)
```
                             Table "public.users"
     Column      |           Type           | Nullable |      Default
-----------------+--------------------------+----------+-----------------
 id              | uuid                     | not null | gen_random_uuid()
 email           | character varying(255)   | not null |
 full_name       | character varying(255)   | not null |
 hashed_password | character varying(255)   | not null |
 role            | character varying(50)    | not null |
 is_active       | boolean                  | not null | true
 created_at      | timestamp with time zone | not null | now()

Indexes:
    "users_pkey" PRIMARY KEY, btree (id)
    "uq_users_email_lower" UNIQUE, btree (lower(email::text))
Check constraints:
    "ck_users_role" CHECK (role::text = ANY (ARRAY['admin','employee']::text[]))
```

### Column Reference

| Column | PostgreSQL Type | Nullable | Default | Constraint | Reason |
|---|---|---|---|---|---|
| `id` | `UUID` | NOT NULL | `gen_random_uuid()` (server) | PRIMARY KEY | UUID primary key generated by PostgreSQL 17 directly via `gen_random_uuid()`. Stable across environments, no application-side UUID generation needed. |
| `email` | `VARCHAR(255)` | NOT NULL | — | Unique via `uq_users_email_lower` index | User identity. Stored and matched case-insensitively. See uniqueness design below. |
| `full_name` | `VARCHAR(255)` | NOT NULL | — | — | Human display name shown in UI and audit logs. |
| `hashed_password` | `VARCHAR(255)` | NOT NULL | — | — | Password digest only. Plain text passwords are never stored at any layer. |
| `role` | `VARCHAR(50)` | NOT NULL | — | `ck_users_role`: `role IN ('admin', 'employee')` | Controls which operations a user may perform. See role design below. |
| `is_active` | `BOOLEAN` | NOT NULL | `true` (server) | — | Account status flag. Deactivating a user blocks login without deleting the record. |
| `created_at` | `TIMESTAMPTZ` | NOT NULL | `now()` (server) | — | Audit timestamp of account creation. Timezone-aware (`TIMESTAMPTZ`). |

---

### Role Design: VARCHAR + CHECK vs. ENUM

**Decision**: `VARCHAR(50)` with a named `CHECK` constraint (`ck_users_role`) rather than a PostgreSQL `ENUM` type.

**Rationale for CHECK constraint**:
- Simple to modify in Ring 4, when fixed roles are replaced with configurable per-organization roles stored in a dedicated table. Dropping the constraint is a single statement: `ALTER TABLE users DROP CONSTRAINT ck_users_role;`
- Adding a new allowed value today: `ALTER TABLE users ADD CONSTRAINT ck_users_role CHECK (role IN ('admin', 'employee', 'viewer'));` — zero downtime.
- No custom DDL type to create, drop, or maintain.
- PostgreSQL `ALTER TYPE ... ADD VALUE` cannot be wrapped in a transaction and has no `DROP VALUE` equivalent, making ENUM evolution risky.

---

### Case-Insensitive Email Uniqueness

Two complementary layers enforce uniqueness regardless of input casing:

1. **Database layer (primary enforcement)**: A functional unique index `uq_users_email_lower` defined as `UNIQUE, btree (lower(email::text))`. PostgreSQL enforces this at every write, including raw SQL inserts that bypass the ORM.

2. **ORM layer (canonical storage)**: A `@validates("email")` decorator on the `User` model strips whitespace and converts to lowercase before the value reaches any SQL statement. This means stored emails are always in lowercase form.

**Coverage**: Both the ORM validator test and a raw-SQL-bypass test are included in `backend/tests/test_user_model.py`, proving the database-level index catches violations even when the model validator is bypassed.
