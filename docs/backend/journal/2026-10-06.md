- **Problem & Fix (SQLAlchemy Version Pinning)**:
  - *Problem*: `pip install sqlalchemy` pulled `sqlalchemy==2.1.3`. `AGENTS.md` explicitly specifies SQLAlchemy 2.0.
  - *Fix*: Uninstalled and re-pinned SQLAlchemy to `sqlalchemy==2.0.54`:
    ```powershell
    uv pip install "sqlalchemy==2.0.54" --python backend/.venv/Scripts/python.exe
    ```
  - Re-froze requirements into `backend/requirements.txt` (UTF-8, without BOM).

### Phase 3: Docker & WSL Virtualization Configuration
- **Action**: Configured Docker Desktop with WSL2 backend.
- **Problems & Fixes**:
  - *Problem 1 (BIOS Virtualization)*: Docker Desktop failed to boot because hardware virtualization was disabled in BIOS firmware.
    - *Fix*: Enabled CPU Virtualization (Intel VT-x / AMD SVM) in the machine's motherboard BIOS settings and rebooted.
  - *Problem 2 (Virtual Machine Platform)*: The Windows component `VirtualMachinePlatform` was not active.
    - *Fix*: Ran Windows DISM command to enable the optional feature:
      ```powershell
      dism.exe /online /enable-feature /featurename:VirtualMachinePlatform /all /norestart
      ```
  - *Problem 3 (WSL Kernel Outdated)*: WSL required kernel updates to run WSL2 containers properly.
    - *Fix*: Executed subsystem updates:
      ```powershell
      wsl --update
      wsl --set-default-version 2
      ```
      Verified running WSL `3.0.1.0` with Linux kernel `6.18.40.1-1`. Docker Desktop started successfully using Linux containers.

- **Action**: Started the database container and applied the initial migration to enable `pgvector`.
- **Commands Executed**:
  ```powershell
  docker compose up -d
  docker compose ps
  cd backend
  ..\backend\.venv\Scripts\alembic.exe init migrations
  ```
- **Configuration**:
  - Updated `backend/migrations/env.py` to add `backend` to `sys.path`, import `settings` from `app.core.config`, and set `sqlalchemy.url` to `settings.DATABASE_URL`.
- **Migration Execution & Verification**:
  - Created migration script `backend/migrations/versions/6dd2ff08b0bb_enable_pgvector_extension.py`:
    ```python
    def upgrade() -> None:
        op.execute("CREATE EXTENSION IF NOT EXISTS vector")

    def downgrade() -> None:
        op.execute("DROP EXTENSION IF EXISTS vector")
    ```
  - Ran migration:
    ```powershell
    backend\.venv\Scripts\alembic.exe upgrade head
    ```
  - Ran migration a second time to verify idempotency (exited cleanly without error).
  - Verified extension installed in PostgreSQL:
    ```powershell
    docker compose exec postgres psql -U postgres -d orgbrain_legal -c "SELECT extname, extversion FROM pg_extension WHERE extname = 'vector';"
    ```
    Output confirmed `vector` `0.8.7` installed.
